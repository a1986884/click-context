# 0.7.160 慢存储与输入法收尾候选

本轮继续改善草稿写入体验，不上传 GitHub，不改 AI 服务、提示词或原安装页；原生版本号保持 0.7.98。

## 变更

- 草稿写入保持顺序，但等待中的按键只保留最新完整输入，不再逐个排队写过时的中间文本。正在执行的写入仍会完成，以取得下一次冲突检查所需快照。
- 保存、取消会等待最新待写内容处理完，避免清理后旧写入又创建草稿。冲突自动分副本仍保留。
- 只有尚未暂存成功或暂存失败时才注册 beforeunload 提醒；成功暂存、正式保存或取消完成后立即移除。阅读器销毁也移除，迟到回调不能重新安装提醒。
- compositionend 主动同步输入框最终值，覆盖缺少最终 input 事件时的提交与取消选字场景，避免留下临时拼音。

## 验证

997 项完整本地测试通过，语法/manifest 与用户脚本构建通过。

新增测试包含：慢存储时 200 次后续输入只产生“在途值 + 最终值”两次写入；旧失败不覆盖新成功反馈；最新失败重试；flush 等待新队列；离开提醒仅覆盖未保护输入；取消等待最终内容且不复活草稿；销毁与迟到失败清理监听；输入法提交/取消收尾；正式保存成功后迟到草稿失败不再产生离开提醒；阅读器销毁集成。

参考：https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event 。beforeunload 仅是支持该能力的浏览器中的补充提醒，不能拦截手机强杀、保证操作系统终止前写入完成，也不能自行定制提示文字。尚未 iPhone 真机验收。慢存储与输入法事件的边界分支由自动测试覆盖，不冒充真实故障或真机验收。
