# 0.7.158 草稿冲突保护候选

本轮继续改善编辑的数据保护，不上传 GitHub，不改 AI 服务或提示词，原生版本号仍为 0.7.98。

## 变更

草稿新增 revision，每次写入返回新快照。编辑器按顺序写入，并携带自己最后看到的快照；保存、取消、放弃草稿也携带快照。若存储中的草稿已变化，则拒绝旧写入/清理，保留新草稿。旧版无 revision 的草稿仍可读取和恢复。

- 取消旧编辑时发现其他窗口已写新草稿，会关闭本次编辑、保留新草稿，并展示其恢复入口。
- 过期的放弃按钮会刷新恢复提示，要求先核对最新内容，不删除新草稿。
- 保存正式释义成功后若草稿已变化，保留其他窗口草稿并提示核对；不把它当成可直接覆盖的正式记录。
- 冲突时输入框仍保留本窗口文字；不会提供反复强行覆盖的重试。
- 原生扩展生词本消息适配器保留冲突错误码；后台写入保持串行。未进行原生安装验收。
- 预览通过可用的 Web Locks 将同一来源多个窗口的存储写入串行化。缺少该能力时保留每次写入前的快照检查，但不能保证跨窗口完全同时操作的原子性。

用户脚本不同网站之间共享 GM 存储，而 Web Locks 限于来源；本轮没有为跨网站用户脚本提供全局原子锁，不宣称其所有同时竞态已解决。

## 验证

全量 980 项本地测试通过，语法/manifest、用户脚本构建通过。新增旧写入/清理拒绝、取消保留新草稿、过期放弃刷新、异步锁协调独立 store、保存后保留新草稿等测试；后台测试验证 DRAFT_CONFLICT 透传。

Web Locks 实现参考：https://www.w3.org/TR/web-locks/ 。
